# MKT の数学学習記録 (mkt_math)

息子の数学の学習を記録するウェブアプリ。練習問題ごとに時間を計測して正解数を記録し、
講義ビデオの視聴時間も学習として計測する。正答率や学習時間の推移、苦手な問題、
連続学習日数などをダッシュボードで見る。

- 練習問題の本文と答えを画面に表示する（数式は KaTeX で描画）
- 見た目は**シンプル**と**クエスト（RPG風）**の2種類。ヘッダーのボタンでいつでも切り替えられる
- 閲覧は誰でも可（ログイン不要）
- 記録の入力・編集はログインしたオーナーのみ
- スマホ・PC・タブレットで同じデータが見える（Supabase）

## セットアップ

### 1. Supabase

1. Supabase でプロジェクトを作成する。
2. SQL Editor で次の順に実行する。
   - `supabase/migrations/20260915000001_init.sql`
   - `supabase/migrations/20260915000002_rls.sql`
   - `supabase/migrations/20260916000001_video_sessions.sql`
   - `supabase/seed/seed_daisu1.sql`
3. 検証: 代数1の問題数合計が **101** になること。
   ```sql
   select sum(problem_count) from public.exercise_sets es
     join public.categories c on c.id = es.category_id where c.name = '代数1';
   ```
4. Authentication → Users から自分のアカウントを手動で作成する。
5. Authentication → Sign In / Providers で **新規サインアップを無効化**する。
   これにより「認証済みユーザー = オーナー本人」が成立し、RLS の書き込みポリシーが意味を持つ。

### 2. ローカル開発

```bash
cp .env.example .env.local   # VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY を記入
npm install
npm run dev
```

### 3. GitHub Pages へのデプロイ

1. リポジトリの Settings → Secrets and variables → Actions に
   `SUPABASE_URL` と `SUPABASE_ANON_KEY` を登録する。
2. Settings → Pages の Source を **GitHub Actions** にする。
3. `main` に push すると `.github/workflows/deploy.yml` がデプロイする。

リポジトリ名が `mkt_math` 以外の場合は `vite.config.ts` の `base`（または環境変数
`VITE_BASE_PATH`）を `/<リポジトリ名>/` に合わせる。

## 設計上の決めごと

- **講義ビデオは `video_sessions` という別テーブル**にしている。`sessions` に混ぜて
  `exercise_set_id` や `correct_count` を nullable にすると、正答率の集計に
  うっかりビデオが混ざる余地が生まれるため。ビデオは**学習時間・連続学習日数・草グラフ**には
  数えるが、**正答率・1問あたりの秒数・苦手ランキングには一切関わらない**。
  この境界は `src/stats/selectors.ts` の関数シグネチャで表現している
  （正答率系は `SessionWithSet[]` だけを受け取り、時間系だけが両方を受け取る）。
- **正答率の分母は `sessions.problem_count_snapshot`**。マスタの `problem_count` は使わない。
  後から「この練習問題は実は10問だった」と修正しても、過去の正答率が遡って変わらないようにするため。
- **日付は JST で確定させる**。`sessions.study_date` が JST の生成列で、ストリークも日次集計も
  すべてこれを基準にする。クライアント側では `'YYYY-MM-DD'` 文字列のまま扱い、`new Date('2026-09-15')`
  のようなパースはしない（ローカルTZ解釈でオフバイワンが出るため）。
- **タイマーは壁時計ベース**。localStorage に開始時刻を置き、表示のたびに `Date.now()` から
  再計算する。`setInterval` でカウンタを加算しない（バックグラウンドタブでスロットリングされ狂う）。
  リロードや画面ロックを跨いでも正しい。計測対象は練習問題と講義ビデオのどちらでもよい
  （`TimerTarget`）。
- **計測は画面遷移では始まらない**。練習問題やビデオを選ぶと「何を計測するか」が
  クエリ文字列（`?set=<id>` / `?video=1`）に入るだけで、その画面の**スタートボタン**を
  押して初めて時計が動く。選び間違いで時間が記録に混ざらない。
  選択を URL に置いてあるので、スタート前に再読み込みしても選び直さずに済む。
- **問題文もスタートを押してから出す**。スタート前の画面に出しておくと、時計が
  動いていない間に読んで（あるいは解いて）しまえるので、計測した時間が実際に
  かかった時間より短く出る。問題が見えるのは時計が動いている画面だけにする。
- **練習問題の本文は静的データ**（`src/content/problems.ts`）。PDF「中１数学 代数全解説」から
  起こしたもので、DB には入れない。問題文は記録ではないので、マスタ（`exercise_sets`）と
  混ぜると「正答率の集計対象」と「表示用テキスト」が同じテーブルに同居してしまう。
  ただし**表示している小問の数と、記録に使う `problem_count` がずれると画面が嘘をつく**ので、
  `problems.test.ts` が seed SQL を直接読んで突き合わせている（合計 101 問）。
- **数式は KaTeX**。データ側は `$...$` で囲んだ文字列にしておき、`MathText` が描画する。
  問題文は「日本語の中に数式が混ざったもの」がほとんどなので、文と式を別の配列に
  分けるより読みやすい。KaTeX は色を指定しないので、テーマを変えても数式だけ
  取り残されない。KaTeX と問題文で 260KB ほどあるため、チャートと同じく
  遅延読み込みにしている（`src/components/problems/index.tsx`）。
- **答えは解き終わってから出す**。問題を解いている間の画面には問題文だけを出し、
  ストップ後の入力シートに答え一覧を載せる。どのみち正解数を入れるには丸つけが要る。
  このとき**ストップは時計も実際に止める**。丸つけをしている間も数字が増え続けると
  「押しても止まらない」画面になるため。キャンセルすると一時停止で残るので再開できる。
- **保存に失敗した記録は捨てない**。オフラインやトークン切れで書き込めなかったときは
  localStorage に退避し、その場でバナーを出して再送を促す（練習問題・ビデオの両方）。
- **統計はすべてクライアント側の純関数**（`src/stats/selectors.ts`）。全セッションを1本の
  クエリキャッシュに載せて集計する。指標の追加にマイグレーションが要らない。数千行までは
  この方針で問題ない。
- **ルーティングは HashRouter**。GitHub Pages に SPA フォールバックがないため。
- **色は直接書かず、意味のあるトークンを使う**。`text-slate-500` ではなく `text-ink-soft`、
  `bg-white` ではなく `bg-surface` のように書く。トークンの実体は `src/index.css` の
  `@theme` にあり、クエストテーマは `[data-theme="quest"]` で同じ変数を上書きするだけ。
  これにより、コンポーネントを触らずにテーマが増やせる。
- **チャートの色も CSS 変数経由**（`src/components/charts/chrome.tsx` の `CHART`）。
  SVG の `fill`/`stroke` は `var()` を受け付けるので、テーマを切り替えると
  再描画なしでグラフの色も変わる。
- **チャート配色は検証済みの固定順**（`--color-series-*`）。色覚多様性のもとでも
  隣接系列が区別できる並びなので、順序を入れ替えない。明るい面（シンプル）と
  暗い面（クエスト）はそれぞれの背景色に対して個別に検証してある。
- **クエストテーマの LV／RANK は表示だけの派生値**（`src/stats/quest.ts`）。
  記録しているデータは何も変わらず、解いた問題数を経験値として見せているだけ。
- **ドット文字は ASCII の箇所にしか使わない**（`.display` クラス）。
  日本語に当てると Web フォントの巨大なサブセットを読み込むことになるため、
  タイマーや LV など数字・英字だけの場所に限っている。
- **大分類・練習問題はハードコードしない**。設定画面（`/manage`）から追加・編集できる。
